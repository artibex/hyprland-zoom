# hyprland-zoom 0.2 — Architecture and contracts

This document is the design contract of the 0.2 rewrite. Every component codes against the
contracts C1–C9 below; a change to a contract is a change to this file first.

Target: Hyprland **0.55+ with the Lua config** (verified on 0.56.2). Hyprland with the legacy
hyprlang config keeps a best-effort fallback (E8).

## Decisions

| ID | Decision | Why |
|---|---|---|
| E1 | The zoom logic runs **inside Hyprland** as a Lua engine (`hyprland-zoom.lua`) that the user's `hyprland.lua` loads with `dofile`. Scroll and key binds are Lua functions. | A spawned `zoomctl` per scroll notch did get-then-set through `hyprctl`: 20 concurrent notches lost 17–19 steps (race) at ~39 ms each. In-process Lua is atomic and takes microseconds. |
| E2 | The engine sets `binds.scroll_event_delay` (default **0**, setting `SCROLL_EVENT_DELAY_MS`). | Hyprland's default 300 ms drops every further notch inside the window **and passes it to the focused app** — the "one notch zooms, the next scrolls the page" bug. |
| E3 | One settings schema (`config/settings.schema`, C1) is the single source for keys, types, defaults, ranges and labels. Bash, Lua and the GUI all read it; nobody hard-codes defaults or ranges. | Validation in three languages must not drift. |
| E4 | `zoomctl` is the **only writer** of the user config file. The GUI and scripts change settings through `zoomctl set`; the engine only reads config files. | One writer, one validator, no lost updates between GUI and CLI. |
| E5 | Pointer tracking modes map to Hyprland's native camera options; a configurable edge margin needs the optional C++ plugin `hyprzoom` (E6). Without the plugin, `margin` falls back to `edge` (fixed 5 % margin) and status reports the effective mode. | The 0.9 camera box is a literal in `MonitorZoomController.cpp`; Lua has no camera access and no pointer-move event. |
| E6 | Optional plugin `hyprzoom` (`plugin/`, built by `hyprpm` from this repo) hooks `CMonitorZoomController::zoomWithDetachedCamera` and reads `plugin:hyprzoom:edge_margin`. It refuses to hook when the symbol is missing. Not installed by the Arch package. | Plugins are ABI-bound to the exact Hyprland build; hyprpm rebuilds them on update. |
| E7 | Color filters are GLSL screen shaders generated by the engine from templates into `$XDG_RUNTIME_DIR/hyprland-zoom/`, one file name per content hash, set through `decoration.screen_shader`. A screen shader the user had before is remembered and restored when the filter is switched off. | Hyprland applies the screen shader after the zoom, on the final image; the path must change for Hyprland to reload it. |
| E8 | Legacy hyprlang Hyprland: `hyprland-bindings.conf` binds `exec zoomctl …`; `zoomctl` serialises with `flock` and does the math in bash. Tracking/filter via `hyprctl keyword`. Best effort, no GUI live preview guarantee. | Arch ships 0.55+; keep old installs working without spending design effort on them. |
| E9 | The engine keeps the zoom animation (`zoomFactor` leaf) **enabled** at all times; "instant" means the smallest speed (0.1). | With the animation disabled, re-entering the same zoom level reuses a stale camera (Hyprland quirk). |
| E10 | Hyprland reload (Omarchy reloads on every config save/theme change) resets all options and the Lua state. The engine persists `{zoom, saved_zoom, filter_active}` to the state file (C5) on change and restores it at load when `ZOOM_RESTORE_ON_RELOAD` is on. | Otherwise every theme switch snaps an active zoom back to 1.0. |
| E11 | Default binds avoid Omarchy collisions; see C7. When `BIND_TAKEOVER_OMARCHY` is on, the engine unbinds Omarchy's `SUPER+ALT+mouse_up/down` (group cycling) and re-routes Omarchy's own zoom binds (`SUPER+CTRL+Z` in, `SUPER+CTRL+ALT+Z` reset) to the engine, so two zoom engines never fight over `cursor.zoom_factor`. | Both binds fire on the same combo otherwise. |
| E12 | Step model: `ZOOM_STEP_MODE=multiply` (default) multiplies the zoom by `1 + ZOOM_STEP` per notch, `add` adds `ZOOM_STEP`. Zoom is clamped to `[ZOOM_MIN, ZOOM_MAX]` ⊆ [1, 10] and kept as a Lua double (Hyprland stores float32). | Multiplicative steps feel even at every zoom level (macOS behavior); Hyprland 0.56 does no range check on the Lua path (0.57 does). |
| E13 | User-visible text is US English ("color", "centered"). | One spelling across schema, CLI, UI and docs. |

## Contracts

### C1 — Settings schema (`config/settings.schema`)
Line format, `|`-separated, `#` comments and blank lines ignored:
`KEY|TYPE|DEFAULT|CONSTRAINT|GROUP|LABEL|HELP`
- `TYPE`: `float` (CONSTRAINT `min..max`), `int` (`min..max`), `bool` (empty; values
  `on`/`off`, input aliases `1/0/true/false/yes/no`), `enum` (CONSTRAINT `a,b,c`),
  `key` (a Hyprland key name, empty = bind disabled), `mods` (modifiers joined by ` + `).
- `GROUP`: UI page id: `zoom`, `tracking`, `filter`, `shortcuts`, `advanced`.
- Canonical stored form: floats with two decimals (`1.50`), bools `on`/`off`.
- CLI aliases: lowercase key with `_`→`-` and without the `ZOOM_` prefix (`step`, `step-mode`,
  `tracking`, `edge-margin`, `filter`, `filter-contrast`, `bind-key-in` …) plus the
  0.1 aliases (`center-cursor` → `ZOOM_TRACKING`, see C2).
- Cross-field rules (all validators): `ZOOM_MIN <= ZOOM_RESET <= ZOOM_MAX`.

### C2 — Config files
- System: `/etc/zoomctl.conf` (`ZOOMCTL_SYSTEM_CONFIG` overrides), user:
  `${XDG_CONFIG_HOME:-~/.config}/zoomctl/zoom.conf` (`ZOOMCTL_USER_CONFIG` overrides).
- Format `KEY=VALUE`, one per line, `#` comments, no quotes needed, values trimmed. Effective
  value = schema default ← system ← user. Unknown keys are ignored with a warning; invalid
  values fall back to the next layer with a warning (never abort the compositor).
- 0.1 compatibility: `ZOOM_CENTER_CURSOR=1` and no `ZOOM_TRACKING` → `centered`;
  `ZOOM_CENTER_CURSOR=0` and no `ZOOM_TRACKING` → `edge`. A file that contains
  `ZOOM_CENTER_CURSOR` (0.1 format) but no `ZOOM_STEP_MODE` implies `ZOOM_STEP_MODE=add` for
  that layer, so a 0.1 step value keeps its meaning. `zoomctl set` rewrites the user file with
  canonical keys, writes the implied values explicitly and drops `ZOOM_CENTER_CURSOR`.

### C3 — Engine Lua API (global table `HyprZoom`)
All functions return a short string (never empty) for `hyprctl repl` and never raise into
Hyprland (errors → `hl.notification` / log + return `"error=<text>"`).
- `HyprZoom.zoom_in(notches)`, `HyprZoom.zoom_out(notches)` — default 1 notch.
- `HyprZoom.set_zoom(factor, remember)` (`remember=false`: transient, e.g. a UI test zoom, leaves
  `saved_zoom` untouched), `HyprZoom.toggle()`, `HyprZoom.reset()`.
- `HyprZoom.filter(action)` — `"on" | "off" | "toggle" | <filter name>`.
- `HyprZoom.reload()` — re-read schema + config files, re-apply binds, tracking, filter, animation.
- `HyprZoom.preview(overrides_table)` — apply overrides (schema keys → values as canonical
  STRINGS exactly as in a config file, e.g. `{ZOOM_STEP="0.15"}`; the engine validates them with
  its config validator) live without writing anything; `HyprZoom.preview_end()` — drop
  overrides, re-apply the saved config.
- `HyprZoom.status()` — `key=value` pairs separated by `\n` (C6 keys).
- The engine is idempotent on reload (`HyprZoom = HyprZoom or {}`; binds are unbound before
  rebinding) and never `io.popen`s in a bind callback (100 ms Hyprland budget).

### C4 — CLI (`zoomctl`)
Engine reachable (Lua config + `HyprZoom` loaded): actions are forwarded with
`hyprctl eval 'HyprZoom.<fn>(…)'`, queries with `hyprctl repl 'return HyprZoom.status()'`.
Otherwise the legacy bash path (E8). Commands (exit 0 = success, 1 = error with message on
stderr, 2 = usage):
- `in [n]`, `out [n]`, `zoom <factor> [--transient]`, `toggle`, `reset`
- `filter [on|off|toggle|<name>]`, `tracking <centered|edge|margin|follow>`
- `set <key> <value>` (validate C1, write user file, then `HyprZoom.reload()`),
  `get <key>`, `unset <key>` (remove the user override), `reset-config` (delete user overrides)
- `config [--porcelain]` — porcelain: every schema key as `KEY=VALUE`, schema order.
- `status [--porcelain]` — porcelain keys in C6.
- `preview <KEY=VALUE>…` / `preview --end` — live preview through C3 (UI "try it" path).
- `setup` — wire the engine `dofile` line into `hyprland.lua` (migrates the 0.1
  `hyprland-bindings.lua` line) or the legacy `source =` line into `hyprland.conf`.
- `doctor` — human-readable checks (Hyprland version, Lua config, engine loaded, include line,
  plugin, conflicting binds, scroll_event_delay).
- `ui` / `configure` — exec `hyprland-zoom-settings`; `edit-config`; `uninstall`; `help`.

### C5 — Runtime state
Directory `${ZOOMCTL_STATE_DIR:-$XDG_RUNTIME_DIR/hyprland-zoom}` (0700). Files: `state`
(`KEY=VALUE`: `zoom`, `saved_zoom`, `filter_active`), `filter-<hash>.frag` (current shader
only; older ones deleted), `previous_screen_shader` (user's own shader to restore). The 0.1
file `last_zoom` under `$XDG_RUNTIME_DIR/zoomctl/` is read once as `saved_zoom` if present.

### C6 — Status keys (`HyprZoom.status()` / `zoomctl status --porcelain`)
`engine` (`lua` = engine answering | `missing` = Lua config without the engine, run `zoomctl setup` | `legacy` = hyprlang config, bash fallback | `unreachable` = no compositor), `version` (package version), `hyprland` (version),
`zoom`, `saved_zoom`, `tracking` (configured), `tracking_effective`, `edge_margin`,
`plugin` (`loaded`|`missing`), `filter`, `filter_active` (`on`|`off`), `filter_shader` (path or
`none`), `scroll_event_delay_ms`.

### C7 — Default binds (all from the schema, modifiers `BIND_MODIFIERS`, default `SUPER + ALT`)
| Action | Default | Schema key |
|---|---|---|
| Zoom in / out | scroll down / up (`down-in`; `up-in` reverses) | `BIND_SCROLL`, `BIND_SCROLL_DIRECTION` |
| Zoom in / out (keys, repeating) | `I` / `O` | `BIND_KEY_IN`, `BIND_KEY_OUT` |
| Toggle zoom | `0` and middle click | `BIND_KEY_TOGGLE`, `BIND_MOUSE_TOGGLE` |
| Toggle color filter | `C` | `BIND_KEY_FILTER` |
| Open settings | `Z` | `BIND_KEY_SETTINGS` |
P1a verifies each default against Omarchy's bind files at implementation time and reports
a collision instead of silently shipping it.

### C8 — Settings app
Executable `hyprland-zoom-settings`, application id `io.github.artibex.HyprlandZoom` (also the
Wayland class; the engine adds a float + center window rule for it). GTK4 + libadwaita via
PyGObject. Reads the schema (C1) and `zoomctl config --porcelain` / `status --porcelain`;
writes only through `zoomctl set|unset|reset-config`; live "try it" through
`zoomctl preview … / preview --end`. Runs as a normal user only.

### C9 — Plugin (`hyprzoom`)
Config `plugin:hyprzoom:edge_margin` (float, fraction of the zoomed view per side, 0.00–0.45,
default 0.05 = native behavior) and `plugin:hyprzoom:enabled` (bool). Lua:
`hl.config({ plugin = { hyprzoom = { edge_margin = 0.15 } } })`; the engine detects it with
`hl.get_loaded_plugins()` (name `hyprzoom`). Build: `hyprpm add <repo>` + `hyprpm enable
hyprzoom` (`hyprpm.toml` at the repo root).
